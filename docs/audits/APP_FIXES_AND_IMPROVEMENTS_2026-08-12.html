What we fixed, in plain English.

The short version: the app was often asking Luna to return a perfect, complicated answer in one try. When one field was wrong, the whole answer could be rejected. We changed that. Luna can now do the work in smaller steps, fix mistakes, and retry temporary service problems.

What was actually going wrong?

Before

  • Luna could understand a request but format one field incorrectly.
  • A short service overload could fail the whole task.
  • Job search could reach the next page and then stop before reading it.
  • The app sometimes called a normal model answer a “fallback” by mistake.
  • A visible button named “Submit application” was mistaken for an instruction to submit.

Now

  • Luna uses simple actions such as “change headline” or “replace this résumé section.”
  • The app fills in technical details such as IDs and timestamps itself.
  • Temporary service problems are retried before giving up.
  • Moving to a new jobs page counts as progress, so the app gets time to read it.
  • The report now tells the difference between Luna succeeding, the app safely rejecting a bad suggestion, and the backup answer being used.

The fixes from this pass

Fixed

Profile Copilot can make normal profile changes

It now has simple actions for identity, summary, skills, job preferences, locations, and salary. It no longer needs to invent the app’s internal bookkeeping fields.

Fixed

Guided Edits can update a résumé section cleanly

Luna can propose the new text while the app creates the safe edit record. Locked content still stays locked, and you still review the change first.

Fixed

Short Luna outages no longer end the task immediately

Temporary overloads, rate limits, timeouts, and network interruptions are retried up to three times. A real long outage still produces an honest error instead of pretending the task worked.

Fixed

Job search can continue through pagination

The worker now treats reaching a different page as useful progress. It can move to page two, read the listings there, keep the useful jobs, and finish instead of looping on page one.

Fixed

Job pages are easier to read reliably

The local reader now recognizes normal job-card details and structured job information before asking Luna to interpret the page. This gives the model better facts and reduces wasted calls.

Fixed

Login walls are handled as login walls

A source check can now report that sign-in is required and save useful guidance. It no longer turns that expected situation into a vague browser failure.

Fixed

Screenshot answers accept harmless wording differences

If Luna calls something a “control” instead of a “visible control,” the app can safely translate it. The app still rejects unsafe action instructions.

Fixed

Seeing a Submit button is not the same as clicking it

The app may record that a Submit application button is visible. It still rejects instructions telling the worker to press it. Final submission remains outside the worker’s authority.

Fixed

Source-check summaries are less fragile

If Luna leaves an optional choice blank, the app uses the safe default instead of logging a large validation error for an otherwise useful result.

What “fallback” means

A fallback is the app’s backup answer. It is used when Luna is unavailable or cannot return a safe usable result. The backup keeps the app useful, but we do not count it as Luna succeeding.

A safe rejection is different. For example, Luna may suggest résumé wording that is not supported by the saved facts. The app rejects that wording and still builds the complete résumé from trusted information. That is the safety system working correctly.

What cannot be guaranteed

A website may be down

The app can retry and explain the problem, but it cannot make another company’s site available.

A source may require login

The app should pause and ask you to sign in. It should not bypass login, CAPTCHA, or account controls.

The AI service may have a long outage

Short problems are retried. A longer outage must still be reported honestly.

Bottom line

The latest hard test passed every major AI area without using the backup answer.

That is much better than the older full benchmark, which was run before these fixes. A new full 110-case run can be done later for broader numbers, but the current 11-case hard test is the reliable acceptance checkpoint for this work.
