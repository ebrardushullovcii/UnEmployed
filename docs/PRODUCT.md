# Product

`UnEmployed` is one local-first desktop app with two modules:

- `Job Finder`
- `Interview Helper`

## Shared Baseline

- shared local profile, documents, reusable answers, and application history
- shared browser runtime, source intelligence, AI provider roles, desktop shell, settings, tray, and hotkeys
- UI-first workflows with agent assistance inside bounded product surfaces

## Job Finder

Current baseline:

- resume import and profile editing with guided setup and profile copilot; each new import saves a private working copy and records the SHA-256 of those saved bytes. The first-run privacy explanation distinguishes the local working copy from optional configured-model analysis, and setup never implies that model processing is purely local. Import locks profile/setup editing until reconciliation finishes so a late import response cannot overwrite a concurrent draft. Existing legacy source references are migrated into app-owned storage when their bytes remain trustworthy; missing, unreadable, or changed legacy files show a replace-resume recovery path without discarding extracted profile details and cannot appear application-ready. Extraction retains every grounded role and bullet, derives work mode only from candidate evidence, keeps skills role-specific, and supplements sparse provider output with deterministic grounded evidence instead of silently dropping supported history. Re-importing unchanged app-owned bytes can reuse local analysis only when parser, provider/model, prompt, schema, reconciliation policy, and candidate-context fingerprints all match; refresh actions intentionally recompute because they do not reread and re-hash source bytes
- browser-driven job discovery across configured targets; setup and Find jobs share one readiness rule requiring a target role plus at least one enabled valid public HTTP(S) source, and disabled search controls explain and link directly to the missing owner. Guided setup includes the same basic source name, URL, and enabled-state editor used by the full Profile flow, and cannot complete while no runnable source exists. Independent public provider inventories begin concurrently, fast public-provider source checks avoid unnecessary browser work, and title/location/work-mode triage plus distinct-role budgets rank useful options against the active resume and target roles. Compact collision-safe known-job aliases, versioned fingerprints, freshness deadlines, and provider update timestamps skip unchanged enriched work early while changed/reactivated listings refresh; one shared identity resolver prioritizes provider/source-scoped posting IDs and normalized employer application URLs, treats exact title + company + location + absolute date only as a possible corroborating alias, and refuses ambiguous or conflicting legacy aliases instead of silently selecting or deleting an unrelated posting; later sources budget from distinct newly retained identities so duplicate-heavy early sources cannot consume their exploration share. Interrupted running discovery becomes an explicit failed/interrupted record while saved jobs and history remain intact
- an evidence-backed fit ledger that separates required, preferred, and inferred requirements; cites exact listing text and resume/profile sources; marks support, missing evidence, uncertainty, and conflicts; and keeps both the numeric score and conservative strong-fit/original-CV/review/skip recommendation grounded in that evidence. Scorer/session version 4 adds typed role suitability, preference alignment, application effort, evidence coverage, and compensation; orders conservative recommendation before aggregate score; rejects non-openings and unrelated role families; and treats geography, clearance, and thin required evidence conservatively. Unknown evidence stays neutral, Easy Apply changes only effort, hard conflicts stay hidden by default, and the full requirement ledger remains inspectable. When a saved result is meaningfully reassessed or changes position in the visible ordering, Job Details preserves the latest change and explains it through a closed `Why this result changed` disclosure; unchanged refreshes do not erase that explanation. The shell reflows all six Job Finder destinations at native Electron 200% zoom, while recommendation badges wrap inside their parent assessment cards
- source-debug that learns reusable target instructions from schema-safe DOM/text evidence and bounded visual evidence
- resume workspace with ATS-first preview, export, approval, template selection, manual experience ordering, explicit editor representation for every canonical work-history record, and an atomic pre-mutation version ledger capped at the newest 100 persisted revisions per draft; exact review-required restore survives restart, clears approval/export readiness, and protects newer edits from stale saves or slow AI regeneration; all eight apply-safe templates use flat recruiter-grade typography, restrained rules and accents, and print-aware entry pagination rather than card-like document chrome; rendered HTML or PDF exports record the SHA-256 of the exact output bytes and preserve their exact format
- a persisted application-CV choice: Settings defines the default for jobs shortlisted later, while every shortlisted job keeps its own `Original CV unchanged` / `Tailor for this job` selection; changing one job never changes another current job or the Settings default, and Apply Copilot remains an explicit per-job action in both modes
- eight apply-safe templates: `Chronology Classic`, `Senior Brief`, `Modern Editorial`, `Engineering Spec`, `Proof Portfolio`, `Formal Proof`, `Longform Timeline`, and `Career Pivot Bridge`
- target-generic prepare-only apply flows that fill exact grounded profile fields, attach the explicitly selected original or tailored resume, advance only clearly non-final steps, and stop at final submission or any ambiguous gate; disposable acceptance runs may separately authorize intermediate ATS writes without authorizing or clicking final submit. Every catalog/browser execution path is normalized to `prepare_only`; legacy submit-capable modes pause without a submitted outcome or timestamp. Tailored approval and both original/tailored pre-apply paths reject missing integrity records, missing files, or SHA-256 mismatches before browser work; readiness names the exact CV, redacted destination, unresolved user work, allowed intermediate writes, and disabled final submit; afterward, each new result carries a redacted receipt and can export a local redacted JSON packet without credentials, raw browser state, URL secrets, or local file paths
- a unified, persisted `Needs you` Action Inbox with distinct login, signup, MFA, email-verification, CAPTCHA, account-choice, manual-answer, legal-consent, redirect, upload, and other presentations. Every classified application blocker persists. Authentication kinds verify source access; challenge/control kinds verify that the exact blocker is absent. Done schedules at most one run/job/result/checkpoint-scoped `prepare_only` retry: the same blocker stays blocked, no blocker resolves, and a changed blocker becomes a new pending request. Stable identity, claim/CAS/idempotency, restart, and multi-instance protections prevent duplicate execution; no request grants credentials, account creation, intermediate-write consent, or final-submit authority
- `Needs you` is visually and semantically separate from the sequential Profile → Find jobs → Shortlisted → Applications workflow, while Settings remains available with the workflow destinations
- discovery keeps Current Search in the same first-column position before and after results arrive; established layouts place Job Results in the center and Job Details on the right
- `Not interested` is an explicit local preference, not a ranking fact: users choose one or more bounded reason chips before hiding a result, hidden jobs remain reviewable in a disclosure, and `Show again and reset` restores the job and clears the feedback. Rediscovery preserves the explicit hidden state across stable aliases while accepting refreshed factual listing and fit evidence
- Search History preserves a typed per-run change digest for new, unchanged, changed, reactivated, inactive, known, and skipped listings, plus duration, warnings, and per-source health. Failed sources can be retried only through the existing single-source operation; history never turns retry into a broad replay.
- tailored-résumé generation exposes a readable labelled progress bar with its estimate outside the fill and keeps the same displayed progress when the user leaves and returns while that operation is still pending
- Resume Studio opens on the live preview and export/approval controls; job context and claim-level evidence stay available in a collapsed native disclosure instead of pushing the primary document task out of view
- Guided Edits stays in a solid floating viewport panel, defaults to the bottom-left, supports drag/maximize/minimize/close controls, clamps to the current viewport, and badges new replies instead of reopening itself or moving the underlying workspace. Approved résumé state names the exact artifact and exposes one clear continuation back to Shortlisted
- Shortlisted exposes one state-driven primary application action above supporting evidence. Its label, enabled state, blocker, and nearby recovery action derive from the selected job and résumé asset, while uncommon proof and diagnostics remain available below or through disclosure
- a global Task center derives truthful stages, source/count progress, supported cancel/restart/review actions, and history-based estimates from persisted run state without a fake countdown
- a bounded local product-action registry lets an assistant read workflow summaries, inspect Needs you and an exact apply run, create review-only Profile Copilot proposals, shortlist/dismiss/restore one job, or open one existing user-action page. Mutations carry explicit confirmation policy and typed receipts; proposal tools never auto-approve, and no tool can submit, create an account, navigate arbitrarily, read files, or mutate an external application
- meaningful edits expose saving/saved/failed state with stale-completion protection, exact retry, guarded navigation, and restart receipts; high-churn workspace updates can arrive as revisioned slice deltas with stale/gap rejection and one-shot full-snapshot recovery
- résumé imports can propose evidence-cited timeline repairs for overlaps, gaps, ambiguous or reversed dates, split/duplicate records, and missing employer/title; every proposal is independently accepted, rejected, or undone with stale-edit protection
- manual application answers distinguish one-use storage from an explicit future Profile save. Suggestions show provenance, prior question, confidence, scope, and revision; they are never inserted automatically and conflicting saved answers are never overwritten
- Settings includes a local Documents & assets library for resumes, cover letters, portfolios, work samples, transcripts, certificates, and images. Imports are copied into app-owned storage, signature/MIME and size checked, SHA-256 verified, and shown to the renderer as metadata only. Each asset carries sensitivity, retention, and an explicit private-storage, application-attachment, or assistant-context consent scope; importing an asset does not automatically attach it to an application or expose its bytes to a model. `until_deleted` remains the default, while 30- and 90-day policies are explicit choices whose clock starts only after import succeeds. Removal or expiry makes an asset unavailable immediately and moves it to Trash for seven days; restore requires an explicit policy and starts a fresh clock, after which ordinary filesystem deletion purges the stored file and metadata. Supporting-file uploads obtain bytes through a main-process-only loader that rechecks lifecycle, consent, size, and SHA-256 immediately before the browser file control is filled, so later removal or tampering blocks the upload. This is recoverable product deletion, not a forensic secure-erase guarantee
- Applications can create a cover letter or short-response document for one exact application and optional file question. Deterministic generation ranks approved profile summary, proof-bank, experience, project, and skill evidence against the exact job and question, removes repeated evidence, and composes a concise proposal from at most three evidence blocks; the preview exposes every excerpt. A user can edit the proposal and save the text only as a new compare-and-swap revision. Edited revisions are marked user-authored and require claim review because their changes are not automatically grounded. Approval is revision-specific, copies the exact text into Documents & assets with the accurate `cover_letter` or `application_response` type and application-attachment consent, and still requires the user to select and save it for the exact file question. Export is a separate local `.txt` action. None of these actions grants account-creation or final-submit authority
- Settings can export a strictly allowlisted local diagnostic JSON containing build/capability/timing/warning summaries while excluding credentials, raw résumés, transcripts, audio, screenshots, browser storage, and private payloads

Hard rule: live submit remains disabled until explicitly re-authorized. Current application runs always keep `submitAuthorized: false` and `accountCreationAuthorized: false`; the final application control is never clicked. See [ADR 0006](adr/0006-safe-non-submitting-apply-boundary.md).

## Interview Helper

Current baseline:

- target-context setup from Job Finder records or direct user input
- rehearsal checks for transcript language, runnable audio/transcription paths, providers, screenshots, assistant responses, and retention defaults
- capture consent is capability-specific: a user can run system-audio-only, microphone-only, or screenshot-free sessions after accepting the core transmission, retention, and visible-surface disclosures
- a visible main-window conversation with explicit text sends, temporary PNG/JPEG/WebP attachments, screen-capture context, assistant replies, and a recent source-labeled transcript
- user-started microphone and meeting/system-audio transcription with queued transient chunks, local-command STT or configured cloud fallback, native-caption intake, and cue generation behind typed provider roles
- live sessions start with an empty transcript and no synthetic cue; standalone Whisper non-speech markers and short recorder-tail fragments are discarded instead of becoming coaching context
- post-session review, export, transcript annotations, delete, and explicit Job Finder follow-up actions
- starting an interview opens visible answer and transcript popup windows by default while the main conversation remains available; the answer popup is a compact interactive assistant with typed sends, pasted or selected image attachments, explicit screen-context capture, answer copy, and hide/reopen controls, while the transcript popup stays optimized for live source text with copy and hide/reopen controls
- popup workspace updates are event-driven rather than renderer reloads so live audio/transcript changes cannot erase an in-progress answer draft or pending image attachment; popup position and size persist across sessions
- personal-story requests without candidate evidence produce a bracketed STAR scaffold instead of invented employers, incidents, technology, timelines, metrics, or outcomes; screenshot-dependent questions use model-backed visual observations when available and otherwise disclose that visual analysis is unavailable instead of guessing from earlier transcript context

- active sessions expose a derived Session health summary for microphone/system-audio signal, transcription backlog and fallback, cue latency and fallback, popup visibility, and the latest recoverable failure. It uses existing local session state, preserves the session on failure, and never writes back to Job Finder automatically\r\n\r\nHard rule: capture, screenshots, attachments, advanced overlays, and model use must stay explicit, visible, auditable, and adapter-owned. See [ADR 0003](adr/0003-interview-helper-live-session-architecture.md) and [ADR 0008](adr/0008-visible-first-interview-helper.md).

## Product Defaults

- desktop shell: `Electron`
- renderer: `React`
- local persistence: `SQLite`
- browser runtime: managed sessions first
- AI: provider abstraction with separate chat, vision, STT, and embedding roles
